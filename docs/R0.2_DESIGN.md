# R0.2 design review — The Pitchroom

## Findings from the actual implementation

The submitted R0.2 work had useful component boundaries and a real C receipt, but its render was unfinished: new tokens replaced `--canvas/--ink` while globals still used the removed variables; most new class names had no styles. The browser displayed an oversized black SVG and unlaid-out text. Compilation did not detect this.

Structural issues: default entry still depended on Focus, the full metric grid competed with the finding, the timeline showed fixed chapters rather than detected events, and live metric values could link to an older evidence snapshot. Interaction issues: the alleged drawer lacked modal focus containment, offline buttons called a Focus-only endpoint, and history was imported without revalidation. These were corrected alongside the visual work.

## Direction and tradeoff

Use a restrained football broadcast stage: navy canvas, muted green pitch, emerald for available actions/accepted evidence, amber and blue for the two fictional teams. An editorial-only page would weaken replay; a dense terminal would bury the finding. Keep the two-column pitch/finding relationship on desktop and put the finding before the pitch on mobile. Do not claim pressing, formations or tracking from event coordinates.

`tokens.css` owns surface, border, text, team and decision colors. `globals.css` implements the actual component classes, bounded SVG dimensions, 40px desktop/44px mobile controls, 6px control radii, visible amber focus and reduced-motion behavior. Use Segoe UI/Arial, tabular score/metric numerals, 23–26px Fan prose and 14px Analyst prose. No photos, video, glow effects or faux continuous player movement.

## Information and interaction hierarchy

1. Synthetic match, score/time and Play Replay. Default30x completes the replay in24 seconds.
2. Automatically detected questions and the main football finding. A detected event binds evidence to its own time; inference never pauses replay.
3. Fan view: concise evidence-bound narrative. Analyst view: same claim/refs plus frozen-window comparison, review status and limitations.
4. Native modal Evidence Drawer: formula, sources, chains and coordinates. Raw JSON and original prefix remain collapsed.
5. Actual tools/handoff/provider receipts in the optional trace. Overlay preview reuses the approved card and original score/time.

The fixed A/B/C chapter shortcuts remain optional. Detected-moment buttons focus the actual event time. Mobile detected moments form a bounded horizontal strip so they do not push the finding out of view. A saved result explicitly says Historical real analysis; Focus alone never claims an agent is running.

## Factual presentation contract

The Analyst selects a typed assertion and the independent Verifier reviews its core, references and drafted prose. Gates reject false cores and invalid quantitative drafts. Approved public facts use finite `bound-facts-v1` summaries from exact receipts; original free-form prose remains in the operator record. This reduces expressiveness deliberately to bind the metric, value and window together. It is not a post-hoc repair of a false core and not a verbatim model quote.
